## What I discovered
I found that the `searchLocation` and `getCurrentLocation` methods inside `src/components/Map/LocationSearch.tsx` were catching errors (for fetch and reverse geocoding API requests) but failing to provide any user-facing feedback. They only logged the errors to the console and handled state updates without notifying the user, which is inconsistent with the application's pattern of using `react-hot-toast` for UI notifications on API failures.

## What I fixed/added
- Imported `toast` from `react-hot-toast` in `LocationSearch.tsx`.
- Added `toast.error('Failed to search location. Please try again.')` inside the `catch` block for `searchLocation` (after filtering out the expected `AbortError`).
- Added `toast.error('Failed to retrieve current location address.')` inside the `catch` block for reverse geocoding in `getCurrentLocation`.
- Standardized the existing `alert()` geolocation error callback to use `toast.error()` for consistency.

## Next Recommended Target
I recommend looking into other unhandled promise rejections or missing `toast` notifications in data fetching logic, especially within the context files (`AuthContext.tsx`) or data retrieval flows that might fail silently.
