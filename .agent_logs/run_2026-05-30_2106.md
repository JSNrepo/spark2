What you discovered.
In `src/pages/Search/SearchPage.tsx`, there was an ESLint error indicating a violation of the `@typescript-eslint/no-explicit-any` rule. The error was caught in a try/catch block where `queryError` was cast to `any` instead of a stricter type. This violates the project's strict typing rules.

What you fixed/added.
I replaced `const err = queryError as any;` with `const err = queryError as { name?: string; message?: string };` in `src/pages/Search/SearchPage.tsx`. This change satisfies the ESLint rule while still allowing the component to check for `err.name` and `err.message` properties in order to silently ignore `AbortError` instances that occur during canceled debounced searches. Verified with `pnpm lint` and `pnpm build`.
