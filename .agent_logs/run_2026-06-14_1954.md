What you discovered.
In `src/components/Map/LocationSearch.tsx`, the `getCurrentLocation` function calls `navigator.geolocation.getCurrentPosition`. The callback performs a reverse geocoding request to `nominatim.openstreetmap.org`. It checked `if (response.ok)` to parse the data, but if `response.ok` was false (e.g., due to API rate limits or server errors), it silently failed. The error wasn't caught or logged, and the user location state (`query`, `onLocationSelect`) wasn't set to a fallback string ('Current Location').

What you fixed/added.
Added an `else` block to the `if (response.ok)` statement that throws an `Error('Reverse geocoding failed')`. This ensures that API failures are now properly caught by the existing `catch (error: unknown)` block, allowing it to correctly fall back to the "Current Location" coordinates safely and log the failure.

Next Recommended Target
Review other network requests for similar unhandled non-ok response statuses to ensure all API calls fail gracefully.
