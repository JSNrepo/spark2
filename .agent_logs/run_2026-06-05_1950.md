What you discovered.
The `searchParkingLots` method in `src/lib/supabase.ts` lacked specific handling for `AbortError`. Because it caught all exceptions generically, any cancelled query (such as when a user typed rapidly in the search input) resulted in a console error output and a returned error state, causing false positive error messages in the application.

What you fixed/added.
Modified `searchParkingLots` in `src/lib/supabase.ts` to check both the `error` object returned directly from Supabase and any `catch (err: unknown)` errors for `AbortError`. In both cases, the function now silently returns `{ data: null, error: null }` instead of logging an error and returning an error payload, preventing the UI from treating request cancellations as application failures.

Next Recommended Target
Review other database query functions in `src/lib/supabase.ts` that might be using `AbortSignal` or might benefit from cancellation features (like fetching map pins on bounds change) to ensure they properly ignore `AbortError` internally as well.
