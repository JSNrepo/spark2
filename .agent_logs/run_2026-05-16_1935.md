What you discovered:
During the scouting phase, I discovered an inefficient algorithm in the `src/components/Map/MapView.tsx` component. The `filteredParkingLots` `useMemo` block was processing the distance between the user and every single parking lot via the expensive haversine formula (`calculateDistance`) *before* applying simple attribute filters (such as `vehicleType` and `minRating`). This resulted in the app performing complex mathematical calculations and object allocations for parking lots that would immediately be discarded by the subsequent filter.

What you fixed/added:
I refactored the `useMemo` computation for `filteredParkingLots` to apply the attribute filters (`vehicleType`, `minRating`) first. Then, it maps the remaining viable parking lots to calculate their distance relative to the user's location, before passing them through a final distance filter. This significantly reduces unnecessary computations and enhances rendering performance.

Next Recommended Target:
The `src/components/Map/LocationSearch.tsx` component handles debounced searching but does not use an `AbortController` when firing `fetch` requests to the Nominatim OpenStreetMap API. This can lead to race conditions where older requests overwrite newer ones if they return later. Adding request cancellation is recommended.
