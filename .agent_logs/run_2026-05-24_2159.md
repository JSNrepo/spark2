## What you discovered
- The `Dashboard.tsx` component was computing the `filteredBookings` array directly in the render body.
- This means that on every single render, an O(N) array filter operation was running, and a new array reference was being allocated.
- This violates performance best practices as it forces unnecessary computations and breaks referential equality for child components.

## What you fixed/added
- Wrapped the `filteredBookings` computation inside a `useMemo` hook.
- It now properly depends on `[bookings, filter]`, so it only recomputes when the bookings data or the selected filter changes.
- Added a comment explaining the optimization.

## Next Recommended Target
- Review other dashboard or list-heavy components (like `ProviderDashboard.tsx` or `SearchPage.tsx`) to ensure all derived state involving large arrays is properly memoized.
