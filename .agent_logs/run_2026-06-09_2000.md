# What you discovered.
In `src/pages/Search/SearchPage.tsx`, the `handleFiltersChange` function was passed as a prop (`onFiltersChange`) to the `AdvancedFilters` component, but it was recreated on every render of the `SearchPage`. When the user interacted with the search page (e.g., typing in the search bar or receiving continuous network updates), `SearchPage` would re-render, passing a new `handleFiltersChange` reference. This unstabilized function prop would break any memoization attempt on the `AdvancedFilters` component, leading to unnecessary re-allocations and re-renders of the filters panel and its inner static elements.

# What you fixed/added.
- Wrapped `handleFiltersChange` in `src/pages/Search/SearchPage.tsx` with `useCallback` to stabilize the function reference.
- Wrapped the `AdvancedFilters` component in `src/components/Search/AdvancedFilters.tsx` with `React.memo()` to prevent O(N) re-render bottlenecks when unrelated parent state changes occur on the Search Page.
- Verified changes using `pnpm lint`, `pnpm tsc -p tsconfig.app.json --noEmit`, and `pnpm build`, resolving the performance issue without breaking existing functionality.
