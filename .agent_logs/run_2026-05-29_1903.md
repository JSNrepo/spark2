# Agent Run Log

## What I discovered
The `LocationSearch.tsx` component performs debounced searches against the Nominatim OpenStreetMap API using `fetch()`. The component was missing an `AbortController` in the `searchLocation` function. If a user typed quickly, changing their query rapidly, multiple requests could be in flight. A slower, older request could resolve after a faster, newer request, causing a race condition where the search results are overwritten with stale data.

## What I fixed/added
Added an `AbortController` using a `useRef` hook in `src/components/Map/LocationSearch.tsx`. Now, when a new search fetch request is initiated, any previous pending requests are automatically cancelled, preventing race conditions and ensuring the search results correspond to the most recent query. Handled `AbortError` appropriately in the `catch` block.

## Next Recommended Target
Review other components making `fetch()` or database calls triggered by user input (like range sliders or filter toggles) to ensure `AbortController` is used to cancel pending requests when state changes rapidly. Specifically check the `AdvancedFilters` implementation and `db.searchParkingLots` method.
